# ADR-0033 · 收件箱 AI 联网检索（Slice N9 / N9.1）

- 状态：已采纳
- 日期：2026-10-03
- 相关：ADR-0005（opencode 接入）、ADR-0015（AI 全链 · 多实体一揽子处置）、ADR-0027（链接阅读 · 首次出站抓取）、ADR-0028（收件箱并行解析）

---

## 1. 背景与反馈

所有者：

> 「我输入了准备一下今年的四级考试，它应该自行去搜索今年四级考试什么时候，作为截止日期；搜索能力需要具备上。」

Slice N2（ADR-0027）已经让系统**读得懂**用户投递的链接（出站抓取首个链接正文），但那需要用户先把链接丢进来。真实使用里更常见的意图是：用户只写一句自然语言（如「准备今年的四级考试」），**系统应当自行意识到缺一个外部事实（考试日期）并去查**，把它作为任务截止日期补全——即从「被动读用户给的链接」升级为「模型主动请求检索」。

本 ADR 定义 Slice N9 / N9.1 的决策：**模型驱动的两阶段检索**、`searchQueries` 契约、**多引擎检索链与相关性过滤**、注入格式与限额，以及随之而来的出站纪律与边界。

## 2. 决策

### 2.1 模型驱动的两阶段检索

解析不再是「一轮出结果」，而是**模型请求 → 服务端检索 → 回喂同一会话第二轮**：

```text
解析首轮 → 输出 searchQueries（≤2 条）→ 服务端逐条检索
        → 把【联网检索】结果回喂同一会话 → 第二轮补全 dueAt / facts
```

- 首轮输出新增顶层 `searchQueries`：`string[]`，**≤2 条**、每条 **≤60 字**，由模型在确需外部信息时主动请求（不需要时为空）。
- 第二轮沿用**同一 opencode 会话**，把检索结果作为补充上下文，修正时间与事实（`dueAt` / `facts`）；**第二轮失败沿用首轮结果**，不阻断。
- 响应新增 `searched: string[]`：**实际执行**的检索问题（供 UI 与审计外的可见性，本身不落盘）。

### 2.2 引擎链、相关性过滤与页摘录

`buildSearchSection` 负责检索与段落拼装：

| 维度 | 规格 |
|---|---|
| 引擎链 | **Sogou 主 → 360 次 → Bing 备**（前序引擎无有效结果时顺序换下一引擎） |
| 相关性过滤 | 每引擎结果过**相关性令牌**：CJK 二元组（去通用词）+ 拉丁词；**不含任何检索词的泛化 / 限流结果视为该引擎失败**并换下一引擎 |
| 全失败 | 返回**空**（`ok:false`）——模型保守处理，绝不编造 |
| 页摘录 | 每条**成功**问题进行**补抓首条结果页正文摘录**（≤900 字，复用 ADR-0027 的 `fetchLinkExcerpt`） |
| 结果数 | **≤5 结果 / 问** |

### 2.3 注入格式与限额

检索结果以固定段落注入第二轮上下文：

- 段落标题 `【联网检索】（…只可据此修正时间与事实，不得编造）`。
- **固定检索主机**；**12s 超时**；snippet **≤300 字**；整段 **≤2600 字**。
- **不落盘、无审计**——检索结果只作解析临时上下文。

### 2.4 流式阶段事件

流式路径（`…/parse-stream`）在检索开始前先发一帧：

```text
{ kind: 'status', status: 'searching' }
```

前端据此显示阶段文案「正在联网检索…」，让「解析中」与「在查外部资料」可区分。

## 3. 安全与出站纪律

联网检索是本系统**第二次出站行为**（首次见 ADR-0027），沿用同等保守纪律：

- **固定主机**：仅访问既定搜索引擎主机，不由模型或用户输入决定目标地址。
- **超时 / 体积**：12s 超时；单问 ≤5 结果；snippet ≤300 字；段落 ≤2600 字；首条页摘录 ≤900 字。
- **不落盘、无审计**：抓取结果仅注入解析上下文，不写 `data/`、不进 `activity.jsonl`。
- **失败静默降级**：任一引擎 / 抓取失败都不抛出，按「无检索结果」继续，**绝不编造日期或事实**。

## 4. 边界

- **仅文本 / 截图条目触发**：文件条目走「文件 = 资料」归一化路径，不触发检索。
- **限流时保守失败**：搜索引擎限流 / 返回泛化页时，宁可无结果（安全优先），也不硬取、不猜。
- **不抓多页、不做 JS 渲染**：只取搜索结果页 + 首条结果页的静态正文，不翻页、不执行脚本、不带登录态。
- **外部波动**：能否补全 `dueAt` 取决于当次检索结果是否含明确日期；结果缺失时模型应正确省略，属预期行为而非缺陷。
- **无新增依赖、无数据模型变化**：检索结果不落地，`searchQueries` / `searched` 为解析临时产物。

## 5. 验证与证据

QA v68（证据 `.qa/v68/`）+ 探针 `.qa/probe-search/`（probe4 / probe5 验证提取器）：

- **实测（N9.1 修复复验）**：输入「准备一下今年的四级考试」→ 同步路径 11813ms 原文 `dueAt:"2026-12-12T09:00:00+08:00"`、`searched=["2026年下半年 全国大学英语四级考试 时间","2026年12月 大学英语四级 报名时间"]`、`facts` 含「笔试 12 月 12 日 9:00–11:20 · 口试 11 月 21–22 日 · 报名入口 cet-bm.neea.edu.cn」；流式路径 11635ms、SSE 含 `"searching"`、`dueAt` 同值。`logs/reverify.log` **15 PASS · 0 FAIL**。
- **服务端冒烟**：`searchQueries` → `buildSearchSection` → `searched`；Sogou 实抓（`fixtures/sogou-sample.html`）提取器命中；`buildSearchSection([])` → `ok:false`。
- **浏览器**：`.ic-ai__stage` 出现「正在联网检索…」（截图 `n68-searching.png`）；390 横溢 0px；console error 0。
- **零残留**：`data/**/*.json`（排除 `activity.jsonl` 与 `data/files/`）前后 41 文件字节级一致（manifest SHA256 `f6fbcc20…`）。
- **首次 QA 未复现 dueAt 的说明**：首轮 QA 当日 Sogou 返回与四级无关的泛化页，模型在「绝不编造」约束下正确省略 `dueAt`（8 条同源 FAIL，非代码缺陷）；N9.1 加固（360 兜底 + 相关性过滤）后复验通过。

## 6. 后果

- **正面**：用户一句自然语言即可自动补全外部事实（如考试日期），收件箱从「被动解析」变为「主动求证」；检索结果永不落盘、失败静默降级，出站面收敛在固定主机与固定限额内。
- **代价**：解析时延上升（含检索与第二轮，实测数秒至十数秒）；结果质量受外部引擎波动影响，`dueAt` 可能缺省。
- **约束**：新增外部依赖面（搜索引擎），因此以固定主机、超时、体积与「不编造」为硬边界；后续若扩展检索来源 / 多页抓取，须新开 ADR。
