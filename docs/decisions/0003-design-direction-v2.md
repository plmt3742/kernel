# ADR 0003 · 视觉方向 v2：C 柔暗夜色 + 柔影悬浮

- 状态：已接受
- 日期：2026-10-02
- 决策者：项目所有者
- 关联：`docs/00-DESIGN-BRIEF.md` §5、`docs/03-DESIGN-SYSTEM.md`、`CHANGELOG.md` v0.3.0

---

## 1. 背景

v0.2 的前端原型采用严格的瑞士/野兽派单色风格：零圆角、1px 发际线、墨底纸字反转、大写等宽微标签。项目所有者在验收时对该方向提出否决，并在三份设计草案中做选型：

- 草案 A（硬瑞士，延续 v0.2）
- 草案 B「暖雾柔光」：暖白、大圆角、柔影悬浮、零边线
- 草案 C「柔暗夜色」：低亮度深灰、柔辉光、低对比、安静排版、圆角 16

所有者明确：**采用草案 C 作为新的基础方向，并融合草案 B 的「柔影悬浮」语言**。

## 2. 决策

**v0.3 起，KERNEL 的视觉基调改为「C 柔暗夜色 + B 柔影悬浮融合」。**

具体：

1. **默认暗色**：暗色成为首选与默认主题（无保存偏好时暗色；已保存的用户切换仍优先）。背景 `#0F0F10`，表面 `#1A1A1C` / 抬升 `#212124`，文字 `#F4F4F5` / `#A1A1AA` / `#929298`（验收校正，全表面 ≥4.5:1）。
2. **柔影悬浮**：卡片/面板/瓦片在静置态即带大模糊、低透明度的柔影，并以一道极淡顶部高光衬托"浮起"；交互卡片/行在悬停时 `translateY(-2px)` + 更深更广的柔影 + 边缘微亮（180–240ms）。深度由**表面阶 + 柔影**表达，而非硬边线。
3. **边缘纪律**：取消硬发际线；即使需要边缘，也只用 `rgba(255,255,255,.06)` 级别的淡边。
4. **圆角 16**：卡片 16px、内部件 12px、胶囊全圆。
5. **唯一强调色收窄为信号**：`#FF5A52` 仅用于焦点/激活/信号，不作大面积填充，亦不作图表数据系列。文字用其过 AA 的变体（暗底提亮 `#FF8A80`，亮底加深 `#B3261E`）。
6. **亮色 = B 语言**：`#F7F6F3` 暖白底、`#FFFFFF` 卡片、`#1C1917 / #665F59 / #6E6862` 文字（验收校正，全表面 ≥4.5:1），柔影、圆角 16；两主题共享几何与排版，只换色彩与高度。
7. **安静排版**：撤下大写等宽重排的微标签，改为低对比无衬线小字；数据与时间仍保留等宽字体（并补 CJK 回退）。

## 3. 理由

### 3.1 低亮度与长时间阅读

系统是供个人高频、长时间使用的"驾驶舱"。低亮度深灰 + 低对比，比满屏纯黑/纯白更护眼、更耐看，也更贴合"夜间"这一主要使用场景。

### 3.2 柔影表达层级优于硬线

硬发际线在低 DPI/移动端易碎、易噪。用表面阶 + 柔影建立深度，层级更连贯、更有物理感，也让"桌面上的一叠卡"这一隐喻成立。

### 3.3 强调色纪律在暗色下更重要

暗底上大色块刺眼且廉价。强调色收窄为信号，保证它出现时必然有意义（焦点、激活、告警）。

### 3.4 融合而非二选一

C 的柔暗基底解决了 B 的亮白在夜间刺眼的问题；B 的柔影悬浮解决了 C 可能"平"的问题。两者互补，得到既有氛围又有层次的界面。

## 4. 取代与保留

- **取代**：v0.2 的硬瑞士风格（零圆角、1px 发际线为主边界、墨底纸字大面积反转、大写等宽微标签作为默认层级手段）。
- **保留**：通用循环的信息架构、视图规格、单色/图案区分数据的原则、单一强调色纪律、Motion + View Transitions 动效体系、reduced-motion、键盘可达、响应式与移动端底部标签栏、全部功能与数据纪律。

## 5. 后果

- `src/styles/` 五个文件按 v2 重写；`tokens.css` 为唯一事实源。
- 新增过 AA 的强调色文字变体 token：`--accent-text` / `--accent-on-ink`。
- `index.html` 的 FOUC 脚本与 `ThemeContext` 的默认值改为暗色。
- 宪法 `docs/00-DESIGN-BRIEF.md` §5 升版为 v2；`docs/03-DESIGN-SYSTEM.md` 同步。
- 归档的 v0.2 QA 缺陷（M1–M5、P7–P10）一并在此次重做中修复。
- 路线图重编号：视觉重做 = v0.3.0（本次已交付）；数据服务 → v0.4；opencode AI → v0.5；自动化与检索 → v0.6。

## 6. 非目标

本决策不改动信息架构、数据模型、路由或数据纪律；不引入 UI 框架、Tailwind 或新依赖；不做组件改名或结构重构。它是一次视觉与打磨层的方向变更。

## 7. 备选方案

| 方案 | 结果 | 原因 |
|---|---|---|
| C 柔暗 + B 柔影融合（本决策） | 采用 | 夜间护眼、层次柔软、强调色克制，兼顾氛围与深度 |
| 延续 v0.2 硬瑞士 | 否 | 被所有者否决；低 DPI 发际线脆弱，整体偏冷硬 |
| 纯 B 暖雾柔光（亮色主导） | 否 | 亮白在夜间刺眼，不适合主力使用场景 |
