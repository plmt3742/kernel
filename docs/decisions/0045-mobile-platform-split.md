# ADR-0045 · 移动端独立界面（平台分支）

- 状态：已采纳（架构已定；页面构图待设计稿评审）
- 日期：2026-10-21
- 相关：ADR-0012（全站详情居中弹窗）、ADR-0041（分层导航 · 三处同源）、ADR-0039（个人页）、ADR-0040（踪迹）、`docs/00` §3 / §4、`docs/03`

---

## 1. 背景与问题

移动端（≤767px）目前不是一套独立界面，而是**桌面端同一棵 DOM 套媒体查询**：

- 左侧索引轨道在 `@media (max-width: 767px)` 内变成底部标签栏（5 项 + 「更多」打开命令面板）；
- 五类详情仍是**居中 Modal**（660 / 820px），在 390px 屏上接近全屏白框，缺少原生的「推入 / 返回」层级；
- 大量交互依赖 hover（行悬停出动作、卡片抬升），触屏上不可发现；
- 桌面级信息密度（12 列网格、多列卡片、双侧留白）直接压到 390px，只能靠单列堆叠勉强容纳。

所有者 2026-10-21 的要求：

> 需要重新**全量**设计手机版界面，符合手机软件使用习惯，界面要**完全独立**、和电脑端不同，**设计风格保持不变**（比如配色）。

这与 ADR-0041 的「桌面轨道 / 命令面板 / 移动底栏**三处同源**」直接冲突。本 ADR 是对该原则在**移动端**的受控例外：同源的是**数据、路由与设计 token**，不再要求同源组件。

## 2. 决策

### 2.1 平台分支，而不是继续加媒体查询

同一套路由（`/`、`/inbox`、`/tasks` … 全部冻结），由 `PlatformGate` 按视口选择 **DesktopShell** 或 **MobileShell**：

- `< 768px` → 移动端组件树（`src/mobile/**`）
- `≥ 768px` → 现有桌面端组件树（**一行不改**）
- 不引入 `/m/*` 前缀：深链、书签、`?note=` / `?task=` 折叠参数、命令面板跳转全部保持不变。

判定用 `matchMedia('(max-width: 767px)')` + `useSyncExternalStore`（首帧即正确，无闪烁）；本应用为纯前端、无 SSR，不需要 cookie 或 UA 嗅探。

### 2.2 物理隔离与所有权

| 归属 | 路径 |
|---|---|
| 移动端独占 | `src/mobile/shell/**`、`src/mobile/views/**`、`src/mobile/components/**`、`src/styles/mobile*.css`、`src/lib/platform.ts` |
| 桌面端独占（本 ADR 期间不动） | `src/components/shell/**`、`src/views/**`、`src/styles/{shell,views,components}.css` |
| 共享只读 | `src/styles/tokens.css`、`src/lib/**`（数据 / mutations / 派生）、`src/types.ts`、`server/**`、`data/**`、`public/**` |

移动端只消费共享层，**不新增写入路径、不改数据模型**；任何共享层改动按既有纪律走 ADR + `docs/04`。

### 2.3 桌面端不回归

「完全独立」是**加法**：移动端另起一套，桌面端 DOM 结构、样式与交互**零改动**。验收以 1440 / 1280 截图对比为准。

### 2.4 视觉语言不变

复用现有 token，不新增色板：柔暗夜色（默认）/ 亮色、accent 仅作信号、圆角 16 / 12 / 全圆、柔影悬浮、中文为主 + 英文小灰标。移动端只改变**布局、密度与交互语汇**。

### 2.5 移动端交互方向（候选，最终由设计稿裁决）

以下只是给 `MOBILE-P0` 的参考起点，**不是约束**；M 可以在设计稿中提出不同方案：

- 底部 Tab 导航（「更多」可做全屏页，替代命令面板的移动入口）
- 详情可用全屏推入（顶部返回 / 手势返回）或 bottom sheet
- 全局捕捉入口（悬浮动作），下拉刷新（复用 `hydrateFromServer`）
- 触控目标 ≥44×44，`env(safe-area-inset-*)`，`100dvh`，禁 hover-only 可见性
- 输入法弹起不遮挡输入框（对话 / 速记 / 撰写）

**明确不预设**：Tab 数量与项、每页构图、详情形态（全屏 vs sheet）、列表密度——由 `MOBILE-P0` 设计稿提出，所有者选型后定稿。

### 2.6 设计先行，确认后实现

1. `MOBILE-P0`：只出设计稿（`design-drafts/mobile-v1/**`：**13 路由全量**，5 个核心页高保真可交互 + 其余 8 页中保真静态）+ 13 路由移动形态说明 + token 映射；**不写业务代码**。
2. 所有者检阅选型 → 记录到本 ADR §6「设计评审结论」。
3. `MOBILE-P1`：Shell + 核心 4 页；`MOBILE-P2`：其余 9 页；`MOBILE-P3`：全量回归。

## 3. 非目标

- 不做 PWA / 离线 / 推送；不改数据模型与 API；不引入 UI 框架或组件库；不做桌面端改版；不做平板专版（≥768px 归桌面）；不动安装器与启动器。

## 4. 后果

**正面**：移动端可按原生习惯组织信息（全屏层级、底部导航、sheet、手势）；桌面端零风险；两套组件树物理隔离，降低并发冲突；设计稿先评审，避免大返工。

**代价**：双份视图维护；共享层变更需双端回归；移动端 chunk 增加（按路由懒加载）；设计评审多一轮。

**风险**：两套实现容易漂移（同一功能只在一端更新）→ 以「13 路由功能清单」为对照表，P3 逐项勾选；共享派生逻辑变化时必须在两端都跑一次。

## 5. 验证

- 13 路由 × 4 视口（390×844 / 360×800 / 412×915 / 横屏）：零横溢、无居中详情弹窗、可点 ≥44×44、返回可用、console 0 error。
- 桌面 1440 / 1280：截图零变化（或差异仅来自时间 / 数据）。
- `npm run build` 0、`npx tsc --noEmit` 0。
- 文档：`docs/00` §3、`docs/03`、`docs/05`（新目录）、`CHANGELOG`、`TASK_BOOK`、`public/guide.html`。
- 证据：`.qa/mobile-*/`（脚本 + 四档截图 + 前后哈希）。
