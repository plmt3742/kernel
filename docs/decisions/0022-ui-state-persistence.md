# ADR-0022 · 界面状态保留策略（Slice Z）

- 状态：已采纳
- 日期：2026-10-03
- 相关：ADR-0007（AI 周回顾指标口径）、ADR-0010（总览 AI 对话）、ADR-0013（回顾报告与归档）、ADR-0015（AI 全链）、ADR-0017（子任务 + 项目内操作）、ADR-0020（笔记体验）

---

## 1. 背景与问题

所有者反馈：「我每个页面的操作比如首页的 AI 对话，切换页面后再回来就清空了，根本没有保留和记忆。」

根因：多数视图把**界面状态**（筛选 / 分组 / 草稿 / 展开项 / 选中项 / 浏览游标）放在组件 `useState` 里。切换路由时组件卸载，状态随之销毁；刷新则更彻底。此前的例外是 `src/lib/scroll.ts`（模块级 `Map` 记忆各页滚动位置）与 `src/lib/inboxAi.ts`（模块级 AI 解析运行态）——它们是本项目「路由记忆」的既有范式，但仅覆盖滚动与收件箱 AI，未推广到普通界面状态。

本切片（Slice Z）把「界面状态保留」确立为一条**通用策略**：以模块级 store（跨路由存活）为基座，可选叠加 `localStorage`（跨刷新还原），逐页覆盖 F25–F29。

## 2. 决策

### 2.1 机制选择：模块级 store 为主，`localStorage` 为辅；不采用 URL 参数

三种候选：

| 机制 | 跨路由 | 跨刷新 | 返回语义 | 适用 |
|---|---|---|---|---|
| 模块级 store | ✅ | ❌ | 无 | 默认基座（沿用 `scroll.ts` / `inboxAi.ts` 精神） |
| `localStorage` | （经模块 store）✅ | ✅ | 无 | 需要「下次打开还在」的状态 |
| URL 查询参数 | ✅ | ✅ | **支持浏览器前进 / 后退** | 可分享 / 可深链的状态 |

**决策**：统一以**模块级 store**承载界面状态；需要跨刷新记忆的再经 `localStorage` 持久化。**不采用 URL 参数**承载筛选 / 草稿等界面状态，理由：

1. 这些状态**高频且非分享目标**（草稿、展开项、筛选组合），写 URL 会污染历史、让每次点击都产生一条历史记录，前进 / 后退语义反而更乱；
2. 项目已有**深链参数**用于「直达某实体」（`?task=` / `?note=` / `?resource=` / `?event=` / `?project=` 等）——若把筛选也塞进同一命名空间，需额外区分「实体直达」与「视图状态」，复杂度与收益不匹配；
3. `scroll.ts` 已确立刻意**不**动 URL 的先例（滚动位置无法进 URL），界面状态与之一致更简单。

`?resource=` / `?note=` 等实体深链**保持不变**，与本策略正交。

### 2.2 通用助手 `src/lib/uiState.ts`

新增 `createUiStore<T>(key, initial, options)`：

- 模块级 `state` + 订阅者集合（`subscribe` / `get`），配 `useUiStore`（`useSyncExternalStore`）供 React 消费；
- `set` 接受值或 `(prev) => next`；返回**同一引用**时跳过广播（避免无谓重渲染）；
- 模块求值时（`persist !== false`）尝试从 `localStorage` 还原一次：`parse(raw)` 校验 → 非法返回 `null` 则回退初始；
- `persist !== false` 时每次 `set` 写回 `localStorage`，写前经 `prune` 裁剪；
- **读取 / 解析 / 序列化 / 配额写入失败一律静默**（`try/catch` 空处理），绝不阻断界面；
- `persist: false` = 仅模块级（跨路由存活、刷新即重置）。

附 `str` / `bool` / `oneOf` / `oneOfOrEmpty` 小助手，供各 `parse` 安全取值，避免 `as` 断言泛滥。

**命名空间**：键统一 `kernel.ui.<page>.v1`（`chat` / `tasks` / `inbox` / `library` / `calendar` / `projects`；`review` 用 `persist:false` 的占位键）。

### 2.3 逐页口径（F25–F29）

| 项 | 页面 | 保留的状态 | 机制 | 说明 |
|---|---|---|---|---|
| F25 | 总览 AI 对话 | 对话轮次 + 草稿 + 思考中 + 错误 | 模块 store + `localStorage` | `draft`/`busy`/`error` 由组件 `useState` 提升到 store；请求函数 `requestChat` 亦提升到模块级（切路由卸载后仍能把回复写回 store，故「思考中」可跨页保留） |
| F26 | 任务 | 状态 / 时间 / 上下文等筛选、分组模式、更多筛选展开、快速新建草稿 | 模块 store + `localStorage` | `drawerId` / 完成动效 / 草稿弹窗为瞬时态，不保留 |
| F27 | 收件箱 | 选中 id 集、内联展开 id、捕捉草稿 | 模块 store + `localStorage` | 数据版本变化时**对账**剔除已不在未澄清列表的脏 id |
| F28 | 资料 | 标签页（全部 / 笔记 / 资料）、笔记类型、资料类型、资料状态、选中标签 | 模块 store + `localStorage` | 阅读 / 编辑 / 撰写弹窗为瞬时态，不保留 |
| F29 | 日程 | 迷你月历选中日 + 当前显示月游标（以毫秒存） | 模块 store + `localStorage` | 弹窗瞬时态不保留 |
| F29 | 项目 | 快速新建输入草稿 | 模块 store + `localStorage` | 确认弹窗瞬时态不保留 |
| F29 | 回顾 | 周 / 月卡的 AI 草稿运行态（生成中 / 错误 / 草稿） | 模块 store（**不持久化**） | 见 §2.4 |

### 2.4 AI 对话的持久化上限（F25）

- 对话 `turns` **上限最近 60 轮**（`CHAT_MAX_TURNS`）：内存与 `localStorage` 同口径裁剪（`prune`），避免无界增长；超出后最旧轮次丢弃。
- `busy` / `error` **刻意不持久化**：刷新后不存在在途请求，错误也无需回放；`parse` 还原时固定 `busy:false` / `error:''`。
- 还原后按已有轮次推导 id 序号起点（`c-<n>` 的 `max+1`），避免 React `key` 冲突。
- 「清空」语义**不变**：先归档为笔记（`POST /api/notes`），归档**成功**才清空内存并写回空持久化副本（刷新后仍为已清空）；归档失败则对话保留。清空同时自增模块级请求令牌，作废在途响应（迟到不落状态）。
- 请求令牌（`chatToken`）为**模块级**，跨挂载有效——这是「思考中切页返回仍思考中」与「清空后迟到回复丢弃」的关键。

### 2.5 刻意不持久化的东西（What is NOT persisted）

- **收件箱 `pendingFiles`（`File` 对象）**：二进制句柄不可 `JSON` 序列化，且刷新后无法复得；维持组件级（切路由即丢，刷新即丢）。文本草稿 `draft` 已保留。
- **AI 对话的 `busy` / `error`**：见 §2.4。
- **回顾页 AI 草稿（`runtimes`）**：仅模块级（跨路由存活、刷新重置）——报告正文体量大，且草稿绑定归档 `reviewId`，跨刷新回放易产生悬空引用；刷新后重新生成即可。
- **各详情 / 编辑 / 撰写 / 草稿确认弹窗**（`drawerId`、`target`、`editing`、`composeOpen`、`draftTitle`、`draftStartAt` 等）：瞬时交互态，跨路由保留会与 ESC / 焦点 / 深链语义争用，维持组件级。
- **完成动效 `pendingDone`、拖拽态、内联二次确认、聚类提案本地列表等**：纯瞬时视觉态，不保留。
- **数据实体本身**：本策略**只**存界面状态，绝不写 `data/`（见 §3 纪律）。

### 2.6 对账安全（数据变更时）

收件箱在数据版本（`revision`）变化时对账：选中 id 集与展开 id 均按「当前未澄清列表」过滤，剔除已澄清 / 撤销 / 水合移除的 id；无变化则返回原引用（不广播）。其余页面状态为自洽的枚举 / 草稿，无需对账。

## 3. 纪律

- **界面状态 ≠ 数据**：`uiState` 只承载筛选 / 草稿 / 展开 / 选中 / 游标，**绝不落盘 `data/`**；所有数据写入仍经单写者数据服务（ADR-0004）。
- **失败静默**：`localStorage` 读取 / 解析 / 配额失败一律回退，不弹错、不阻断。
- **无新增依赖**：仅用 React 内置 `useSyncExternalStore` 与浏览器 `localStorage`。
- **token-only / 无障碍**：本次未新增样式；保留的状态不改变既有键盘 / 焦点 / `prefers-reduced-motion` 行为。

## 4. 后果

**正面**

- 界面「有记忆」：切页再回来，草稿 / 筛选 / 分组 / 选中 / 展开 / 游标原样还在；聊天与任务筛选刷新后亦还原。
- 机制单一、可复用：一个新助手 `createUiStore` 覆盖六页；不再逐页各写一份 `useState` 迁移。
- 聊天「思考中」跨页保留（请求函数模块化），中途切页不再丢回复；清空后持久化副本同步清空，刷新不回魂。
- 安全侧退避清晰：二进制 / 大文本 / 瞬时交互态明确不持久化并在本文档登记。

**代价 / 已知限制**

- `localStorage` 为**同浏览器同源**记忆；换浏览器 / 清缓存即失忆（本地优先应用的合理边界）。
- 聊天历史上限 60 轮，超出丢最旧（防止配额超限）。
- `localStorage` 键为轻量版本化（`v1`）；日后字段不兼容需升级键名或写迁移（本次未引入迁移面）。
- 回顾页 AI 草稿刷新即丢（刻意），需重新生成。
- 未持久化 `localStorage` 的页面（回顾）跨刷新仍会重置——这是**有意**的取舍，非缺陷。
- 未采用 URL 参数，故筛选 / 分组**不**参与浏览器前进 / 后退；如需可日后按页增补（正交，不冲突）。
