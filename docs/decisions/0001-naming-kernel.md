# ADR 0001 · 项目命名：KERNEL

- 状态：已接受
- 日期：2026-10-02
- 决策者：项目所有者
- 关联：`docs/00-DESIGN-BRIEF.md` §1

---

## 1. 背景

项目需要一个名称与目录名，作为长期标识。候选里最接近的有两个：**KERNEL** 与 **ATLAS**。命名需要同时满足：

1. 与"个人事务内核、本地优先、AI 协作"的定位贴合。
2. 在工作区 `<workspace>` 内不与他人已用的名称冲突。
3. 可形成一致的隐喻体系，便于命名内部概念与组件。

## 2. 决策

采用 **KERNEL** 作为项目名，目录名 `kernel`，位于 `<workspace>\kernel`。

## 3. 理由

### 3.1 KERNEL 与定位高度契合

KERNEL 直接对应操作系统内核隐喻，系统模块可以自然映射：

| 内核概念 | KERNEL 对应物 |
|---|---|
| 进程 | 任务 / 项目 |
| 内存 | 资料 / 知识 |
| I/O | 收件箱 / 通知 |
| 调度器 | 日程 |
| 检索 | 命令面板 |
| GC / 平衡环 | 回顾 |

这套隐喻与"文件即数据库，opencode 即大脑，网页即驾驶舱"的一句话哲学自洽，命名内部概念时不会别扭。

### 3.2 ATLAS 被否：工作区内软命名冲突

ATLAS 本身是合适的候选（地图集、承载全局），但在工作区 `<workspace>` 内存**软命名冲突**：该名称已被工作区内的其他产物在非正式语境中使用，继续采用会在文档、会话、目录引用层面持续产生歧义与检索干扰。

这是"软冲突"而非硬冲突：技术上可以强行重名，但代价是每次提到 ATLAS 都要判断语境，与"新会话 2 分钟冷启动"的目标相背。因此排除。

### 3.3 检索与辨识

KERNEL 在工作区内唯一，大小写与形态明确，便于在会话、文档、代码搜索中稳定命中。

## 4. 后果

- 项目名固定为 KERNEL，目录固定为 `kernel`。
- 文档、代码、注释统一使用 KERNEL。
- 内部概念命名沿用内核隐喻（见 §3.1）。
- 名称若要再次变更，需新开 ADR 并说明迁移影响。

## 5. 备选方案

| 方案 | 结果 | 原因 |
|---|---|---|
| KERNEL | 采用 | 与定位契合，工作区内唯一 |
| ATLAS | 否 | 工作区内软命名冲突 |
