# ADR-0023 · 公告解析：通知三性 + 条件选择 + 截图接入（Slice N0）

- 状态：已采纳
- 日期：2026-10-03
- 相关：ADR-0005（opencode AI 接入）、ADR-0006（AI 解析升级）、ADR-0008（收件箱文件投递）、ADR-0011（状态贯通 · 先确认后写入）、ADR-0015（AI 全链 · 多动作）、ADR-0021（一致性清扫）、ADR-0022（界面状态保留）

---

## 1. 背景与反馈

所有者反馈：「我会将零散微信通知直接丢进去……提取有用信息（放假时间、待办）；这类通知无指明对象，需要判断后让我选择；聊天记录也可能是图片截图；课表属于固定日程要与任务区分（课表是后续切片，不在本 ADR 范围）。」

由此归出三条痛点：

1. **通知 / 公告里混着一堆信息**：放假时间、调课、截止日期是「硬事实」，值得记住却未必是「要你做的事」。既有解析只产出动作（任务 / 笔记 / 资料 / 项目），硬事实无处安放，容易在澄清时被丢。
2. **通知常常没有指明对象**：如「学生出国（境）须提前报备」「留校学生须按时归寝」，是否与你相关取决于你的身份。系统**不该替你默认「要做」**，应把判断交回给你。
3. **截图读不到**：群通知 / 聊天记录常是图片，既有文件管线只按文本摘录或元数据注入，图片内容进不了模型。

本切片（Slice N0）处理第 1、2 条与第 3 条的「读图」；课表（固定日程实体）与画像（个性化）明确留待后续切片。

## 2. 决策

### 2.1 通知的「三性」划分

按信息的**可行动性**分三类，各自归位：

| 类别 | 定义 | 归属 | 说明 |
|---|---|---|---|
| 硬事实 | 放假 / 调课 / 截止日期等客观信息 | 解析响应顶层 `facts: string[]` | **不产实体、不落盘**；UI 以「要点」块呈现 |
| 义务 | 需要**你完成**的动作 | `kind:"task"` 动作（可带 `condition`） | 走既有确认制，勾选后应用 |
| 纯建议 / 安全须知 | 提醒、注意事项、非具体可操作 | **默认不产动作** | 仅**具体可操作**者降级为 `fact` 保留 |

`facts` 契约：**≤8 条**、每条 **≤140 字**、须含日期或关键数字；由 `cleanFacts` 统一 trim / 去空 / 截断 / 去重 / 封顶 8。

- UI 把 `facts` 渲染为安静的**「要点」块**，附一键**「存为要点笔记」**（经既有 `POST /api/notes` 落盘，仍先确认后写入）。
- **facts 不落盘**：它属解析的**临时产物**，重解析可再得；避免在 `data/` 里沉淀无实体归属的中间态（见 §3、§4）。

### 2.2 条件动作：默认不勾选，勾选 = 相关

需完成的义务若带适用前提，`task` 动作新增可选字段 `condition`（**≤30 字**，如「仅出国（境）者」「仅留校学生」）；**对所有人生效则省略**该字段。

- 建议卡中：带 `condition` 的动作**默认不勾选**（默认不下判断，勾选才表示与你相关）；无条件动作维持**默认勾选**（既有行为不变）。
- 勾选即语义「**相关 / 要做**」；动作行显示安静的**「适用：…」**标注，让条件一眼可见。
- 应用负载经 `formToAction` **透传 `condition`**，与其他字段同路径提交。

### 2.3 服务端校验链（不信任客户端形状）

条件的「清理」与事实的「去噪」都在服务端完成，同步与流式两条路径共用：

```text
aiActionSchema.condition（zod ≤30）
        │
        ├─ postValidateActions：null → 清除；非 task → 删除；trim 后空串 → 删除
        │
cleanFacts：trim / 去空 / 截断（≤140）/ 去重 / 封顶（≤8）
        │
tryParseActions() → { actions, facts }
        │  旧式单建议形状经 legacyToActions 归一化 → facts: []
        ▼
同步响应 与 流式 suggestion 事件 均携带 facts
```

`condition` 的运行时约束集中在 `postValidateActions`（与 `projectId` / `areaId` / 标签同属一道快照过滤）：非 `task` 动作一律**不保留**条件，避免无意义字段随动作落库。

### 2.4 截图接入：图片与文本共用同一解析管线

- `isImageFile()`：按扩展名（`.png` / `.jpg` / `.jpeg` / `.webp` / `.gif` / `.bmp`）或 MIME（`image/*`）判定；命中即走图片路径。
- `buildFileSection` 的图片分支：文本摘录换成「**见附图**」单行占位，不再尝试把像素当文本读。
- 解析路径为图片构造 opencode **file part**：`{ type:'file', mime, filename, url:'data:<mime>;base64,…' }`——读取 `data/files/<id>-<name>` 后 base64 内联；**读失败则优雅降级**（退回仅元数据的文本摘要，不阻断解析）。
- **不套用文件硬归一化**：图片**跳过**「文件 = 恰 1 条 resource + 简介」规则（该规则仍适用于非图片文件，行为不变）；提示词让图片条目按**文本多动作规则**处理——通知截图可产任务 / 笔记 / 事实，明显是文章 / 资料时才产 resource。
- 默认模型 `deepseek/deepseek-flash` 已实测**可读图**（探针见 §5），故**无需 OCR、无需更换模型**。

### 2.5 选择信号打底（为后续画像留痕）

`POST /api/inbox/:id/apply` 的审计记录增 `detail.signals.conditions`：本批次**已应用**动作的**非空 `condition` 去重、按首见顺序**。

- 这只是**留痕**，不改动任何行为与数据：**画像本身（`profile.json` / 排序提升 / 条件注入）不在本切片**，属后续切片。
- 已应用的条件事实由此可回溯，供日后「近期关注画像」构建。

## 3. 备选与取舍

| 备选 | 取舍 | 理由 |
|---|---|---|
| OCR（外部识别图片文字） | **否决** | 探针证明本地默认模型 `deepseek/deepseek-flash` 直接可读图（§5）；OCR 徒增依赖与环节，多模态 file part 已够用 |
| 更换视觉模型 | **否决** | 同上——默认模型即可读图，换模型无收益且影响既有解析稳定性 |
| `facts` 落盘 | **否决** | facts 是解析临时产物、无实体归属；落盘会沉淀中间态并需额外生命周期，而重解析可再得 |
| 条件动作自动勾选 | **否决** | 与「无指明对象需你判断」的诉求相悖；默认不勾选、勾选 = 相关，判断权交回用户 |
| 提醒独立桶 / 调休例外 | **延后** | 属日程语义扩展，不在本切片；本切片只把硬事实作为要点呈现 |
| 课表实体（固定日程） | **延后** | 明确不在本 ADR 范围，作为后续切片 |
| 画像注入 / 个性化排序 | **延后** | 本切片只做选择信号留痕，画像构建另立切片 |

## 4. 边界

- **确认制不变**：image / text 共用同一解析管线，结果仍是**建议**；AI **绝不自动应用**（`aiAutomation:'auto'` 的能力边界见 ADR-0016 §2.3，本切片未扩）。
- **facts 不落盘**：属解析临时产物，重解析可再得，`data/` 不沉淀。
- **condition 不写实体字段**：只影响**选择语义**（默认勾选态）与**审计留痕**，不进入任何实体的持久字段。
- **图片抑制 resource 归一化**：仅图片跳过「恰 1 条 resource」硬归一化；非图片文件行为**不变**。
- **后续切片**：提醒独立桶与调休例外、课表实体、画像注入（`profile.json` / 排序提升）均不在本切片。

## 5. 验证与证据

- **读图探针**：程序生成**已知内容**的图片（渲染确定字符串），以 opencode file part 实测默认模型 `deepseek/deepseek-flash` 能否回读内容——证明「无需 OCR / 换模型」（证据 `.qa/probe-vision/`）。
- **确定性契约** `.qa/probe-n0` **10/10**：验证 `condition` 清理（null / 非 task / 空串）、`cleanFacts` 去噪（trim / 去空 / 截断 / 去重 / 封顶）、`tryParseActions` 返回 `{ actions, facts }` 与旧式形状归一化为 `facts: []`、图片分支「见附图」与 file part 构造。
- QA 证据（服务端冒烟 / 浏览器 E2E）将归档 **`.qa/v43/`**（数字见该目录）。
- 未新增依赖；修改均经单写者 + 原子写 + 审计（`inbox.apply` 增 `detail.signals.conditions`）。
