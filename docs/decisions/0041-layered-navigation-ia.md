# ADR-0041 · 分层导航——轨道按功能分四组、移动端收敛为五项 + 更多

- 状态：已采纳
- 日期：2026-10-05
- 相关：ADR-0002（不做身份 / 领域分区）、ADR-0012（全站详情统一弹窗）、ADR-0022（界面状态保留）、ADR-0039（个人页 + 习惯页）、ADR-0040（踪迹）

---

## 1. 背景

项目宪法 §3 明确规定：**一级导航 = 通用循环（总览 / 收件箱 / 任务 / 日程 / 项目 / 资料 / 回顾 / 设置）**。但随着 40 余个功能切片落地，导航发生漂移：

1. **一级项膨胀到 12 项**——课表（Slice H2）、习惯（ADR-0039）、踪迹（ADR-0040）三个新功能各自获得了一个一级轨道座位，加上资料 / 回顾 / 设置 / 回收站，二级 / 工具页与循环页被**等权重**并列。
2. **分组机制名不副实**——`NavItem.secondary` 只在移动端（≤767px）隐藏次要项，**桌面端轨道把 12 项无分组、无分隔、无层级地全部渲染**；命令面板也把 12 项塞进同一个「导航 · NAVIGATE」组。
3. **移动端拥挤**——底栏显示 8 项 + 「更多」共 9 个槽位，390px 屏上每格约 43px。
4. **首启凌乱**——新用户面对 12 扇门 + 空数据 + 无引导（本 ADR 只解决**导航层级**，首启引导见 §3 边界）。

根因：**导航注册表没有准入标准**——每个新功能都被默认授予一个一级座位，「一级导航 = 通用循环」的宪法意图从未真正落地。

所有者也明确反馈：整体页面过多、初次使用体验凌乱。

## 2. 决策

### 2.1 五个功能组（总览置顶，其余四组）

`src/lib/nav.ts` 的 `NavItem` 增 `group: NavGroup`（`home | action | time | record | system`）与 `mobile?: boolean`，取代原先仅移动端生效的 `secondary`。分组如下：

| 组 | 成员 | 语义 |
|---|---|---|
| （置顶，不归组） | 总览 | 驾驶舱——不是循环的一环，单独置顶 |
| **行动 · ACTION** | 收件箱 · 任务 · 项目 · 回顾 | GTD 循环的可操作面：捕捉 / 澄清 → 组织 → 执行 → 复盘 |
| **时间 · TIME** | 日程 · 课表 | 所有「按时间看」的视图（未来若课表并回日程，本组自然收敛为 1 项） |
| **记录 · RECORD** | 资料 · 习惯 · 踪迹 | 非待办、而是沉淀下来的东西：知识 / 打卡 / 动态 |
| **系统 · SYSTEM** | 设置 · 回收站 | 纯工具，视觉权重最低 |

### 2.2 三处同源（轨道 / 命令面板 / 移动端）

分组必须在**同一份数据**上同时生效，避免再次漂移：

- **桌面轨道**：组间加分隔线与安静小灰组标签；`系统` 组视觉最轻。
- **命令面板**：镜像同一套分组（总览单项 + 四个组标题）；**仍可搜全部 12 页**，键盘用户零损失。
- **移动端底栏**：只保留 5 个 `mobile:true` 项（总览 · 收件箱 · 任务 · 项目 · 日程）+ 「更多」（打开命令面板）。组标签在移动端隐藏。

### 2.3 路由冻结（本决策的硬约束）

- **不删除、不合并任何页面**；12 条路由与全部深链（`?task=` `?note=` `?resource=` `?event=` `?project=` `?trace=` `?habit=` `?section=`）**保持不变**。
- 本决策是**呈现层分层**，零导航回归风险；`kernel.ui.*` 界面状态键不改名、不清空。
- 课表 / 习惯 / 踪迹此前均是所有者明确要求「独立成页」——「页面存在」不等于「必须占轨道 C 位」，降权分组不违背任何历史决策。

### 2.4 准入规则（防止再次漂移）

- **新增功能默认进入既有组、作为 hub 页签、或上下文入口（widget / chip / 命令面板），不得默认新增一级项。**
- 需要新增一个**功能组**时，必须开新 ADR，并逐条对照宪法 §3 说明理由。
- 组的增删 / 成员变更统一改 `src/lib/nav.ts` 一处，三处渲染同源。

### 2.5 与宪法 §3 / §4 的关系

本 ADR 是对宪法信息架构条款的**受控修订**：一级导航由「8 项平铺」修订为「总览 + 四组分层」，`docs/00-DESIGN-BRIEF.md` §3 与 §4 相应更新并指向本 ADR。除此之外宪法不变。

## 3. 边界（明确不做）

- **不合并页面**（课表 → 日程 hub、回收站 → 设置、个人 → 设置等均为候选项，各自需所有者拍板 + 独立 ADR）。
- **不做首启引导**（Overview 空数据卡、空态统一、`guide.html` 应用内入口）——单独切片。
- **不做示例数据载入器**（安装包空数据骨架保持不变）。
- 不改变任何数据模型、写入路径或服务端接口。

## 4. 验证

- `npx tsc --noEmit` 退出 0；`npm run build` 退出 0。
- 桌面（≥1280px）轨道显示四组标签与分隔；折叠态（≤1279px 或手动折叠）仅保留分隔不显示标签文字。
- 移动端（≤767px）底栏为 5 项 + 「更多」，390px 零横溢。
- 命令面板分组与轨道一致，12 页均可搜索、跳转正常；`Ctrl+K`、`c` 快捷键与深链行为不变。
- **实测（2026-10-05 · 全新建 dev 实例 + 真实数据服务 · Playwright）**：`qa-nav.py` + `qa-nav-detail.py` + `qa-head.py` **19/19 PASS**——四组标签齐全且**零裁切**（`scrollWidth = clientWidth = 79`）、12 项新顺序、活跃态、折叠态文字隐藏且分隔保留、命令面板四组 + 总览单项、1440 / 390 零横溢、console 0 error；移动端 5 项均分 **65.6px × 5**、与「更多」**零缝隙**。落地过程实测修复三缺陷：单行组标签横向超宽裁切（94–97px > 79px）→ 改双行 cn / en；组标签为列表内唯一 `overflow:hidden` 子项、被 flex 收缩压扁至 13px（自然高 43.6px）→ `.k-rail__list > li { flex-shrink: 0 }`；移动端 `li` 未参与弹性分配（28–38px 内容宽、177px 空隙）→ 移动端 `li { flex: 1 1 0 }` 均分。证据 `.qa/v77/`。
- **已知特征**：1440×900 视口下轨道列表滚动量 300px（平铺基线约 72px；低于一屏的项可滚动到达，如需全量一屏可后续压缩组标签 / 项间距）。
