# ADR-0029 · 来源摘要：一句话摘要 + 引用人话化（Slice N4）

- 状态：已采纳
- 日期：2026-10-03
- 相关：ADR-0005（opencode AI 接入）、ADR-0008（收件箱文件投递 · §6 生命周期）、ADR-0011（先确认后写入）、ADR-0015（AI 全链 · 多实体一揽子处置）、ADR-0023（公告解析）、ADR-0027（链接阅读）、ADR-0028（并行解析）

---

## 1. 背景与反馈

任务详情弹窗的「关联」区块里，指向来源的那一条长这样：标题栏直接把**原文全文**铺进去，旁边再跟一个**冷编号** `i-0001`。所有者两条反馈：

1. 「一条关联引用把原文全塞进来了，太长。」
2. 「为输入收件箱的内容简单总结一下（比如一条日程汇总，包括时间、地点、要做什么），而不是采用什么 `i-1234` 这样子冷冰冰的说辞。」

说白了，来源引用要回答的是「这条任务 / 笔记是从哪句话来的」，而不是把整段原始输入复制一遍；`i-1234` 更是把机器内部 id 直接暴露给用户。本切片（Slice N4）给出**一句话来源摘要**，并让所有对收件箱条目的**引用**都显示人话标题。

所有者在两个方案里选了 B：**关联区块截断 + 完整原文回收件箱查看**，并在此之上追加「AI 一句话摘要」。

## 2. 决策

### 2.1 解析产出一句话摘要

收件箱 AI 解析结果在动作数组（与 `facts`）之外，增顶层 **`summary`**：一句概括原始输入的话。

| 维度 | 规格 |
|---|---|
| 长度 | ≤40 字（硬截断） |
| 形态 | 单行；多要点用「 · 」分隔 |
| 内容 | 覆盖关键时间 / 事项 / 地点等，如「周三 15:00 组会 · 某教室 · 带实验报告」 |
| 纪律 | 只依据原文，**不引入原文外信息**；不出「该内容主要讲述了…」式空话 |
| 清洗 | 服务端确定性清洗：折叠空白、去首尾引号 / 书名号、硬截断 40 |
| 兜底 | 清洗后为空串则回落空串（前端据空串走截断降级，见 §2.3） |
| 落盘 | **不落盘**：解析仍是只读，`summary` 只是解析产物 |

同步 `parseInboxItem` 与流式 `parseInboxItemStream` 共用同一段摘要清洗；流式的 `suggestion` 帧携带 `summary`。

### 2.2 应用时落档

摘要在**应用（apply）** 时随产物一起写入条目，这是刻意的持久化点：

| 层 | 变更 |
|---|---|
| 请求 | `POST /api/inbox/:id/apply { actions, summary? }`（`summary` 可选，≤100 校验） |
| schema | `inboxItemSchema` 增可选 `summary`（≤200 防御性上限） |
| 写入 | 仅当 `summary` 提供且非空时写入条目的 `summary`；缺省 / 空串不写 |
| 审计 | 沿用 `inbox.apply`，不新增审计名 |

只在 apply 落档的理由：解析可重跑、可作废，解析即落档会沉淀中间态并需要额外生命周期；而 apply 是用户确认后的唯一写入点，摘要与产物的来源关系应在这里一起成立。

### 2.3 引用展示人话化

收件箱条目的**引用**（关联区块来源条目、已澄清区产物引用）按下列规则显示：

| 场景 | 显示 | 兜底 |
|---|---|---|
| 关联区块「来源条目」标题 | `summary` 非空优先 | 空则取原文折叠空白后截断 ~90 字 |
| 关联区块来源芯片 | 只显示可见标题，**实体编号入 tooltip** | 无编号可见 |
| 收件箱「已澄清」区产物引用 | 产物**标题**（运行时解析） | 解析不到 / 产物已删则回退 id |
| 完整原文 | 去收件箱「已澄清」区查看，不在关联区块铺开 |  |

由此终结「冷冰冰 `i-1234`」：用户在引用处看到的是一句话摘要，想核对原文再回收件箱。

## 3. 备选与取舍

| 备选 | 取舍 | 理由 |
|---|---|---|
| AI 一句话摘要（本次采纳） | **采纳** | 直接回应所有者诉求；摘要能压缩时间 / 事项 / 地点等要点，比机械截断更贴近「这条是什么」 |
| 纯内容截断（不调 AI） | **否决为主要方案** | 截断只是把长句砍短，信息密度低、易断在半句；保留为**兜底**（`summary` 为空时自动降级） |
| 解析时即落档 `summary` | **否决** | 违背「解析零写入」纪律；解析随时可重跑 / 作废，落档会沉淀中间态并需生命周期 |
| apply 时落档（本次采纳） | **采纳** | apply 是用户确认后的唯一写入点，摘要与产物的来源关系一并成立，复用既有审计 |
| 引用处继续显示 `i-0001` | **否决** | 把内部 id 直接暴露给用户，正是所有者点名要终结的「冷冰冰」体验 |
| 引用处显示原文全文 | **否决** | 长原文撑爆关联区块，信息噪声大于价值 |

## 4. 边界

- 摘要质量受本地模型影响：模型没给 / 给得不好时，服务端清洗后可能为空串，此时展示自动降级为内容截断，**不阻断解析与写入**。
- 历史条目录档前没有 `summary`：展示走截断兜底，**不做批量回填**（旧条目不补）。
- 已澄清区产物引用依赖运行时解析产物标题；产物被删则回退 id。
- 编号只是从「可见」移到 tooltip，**不改变任何 id 与深链**。
- 摘要仍是本机 AI 产物，随解析一起只读；不新增外部调用面。

## 5. 影响面（文件）

- 服务端：`server/ai.mjs`（摘要提示词 + 确定性清洗；同步 / 流式共用）、`server/schemas.mjs`（apply 请求增可选 `summary` + `inboxItemSchema.summary` 可选）、`server/index.mjs`（apply 分支把非空 `summary` 写入 `record.summary`）。
- 前端：`src/lib/mutations.ts`（`applyInbox` 增 `summary?`）、`src/lib/inboxAi.ts`（解析 / 流式结果携带 `summary`）、`src/lib/relations.ts`（来源条目标题从原文改 `summary` 优先 / 截断兜底）、`src/components/Relations.tsx`（芯片可见文本去编号、编号入 tooltip）、`src/views/Inbox.tsx`（已澄清区产物引用显示产物标题）。
- 未改 `data/` 种子；未新增依赖；**无新增写入面与端点**（仅 apply 请求体扩一个可选字段）。

## 6. 验证与证据

QA v61（证据 `.qa/v61/`）：

- **冒烟 25/25**：真实摘要恰好 40 字单行（服务端清洗折叠空白 / 去引号 / 硬截断 40）；apply 落档 → revert 清除；不带 `summary` 的旧调用兼容，产物无该字段；回归 `probe-n2` **23/23** + `probe-h1` **19/19** 不受影响。
- **E2E 24/24**：关联区块来源标题显示 `QA 摘要 · 10/7 面试`（`summary` 优先），`.k-relations` 内无可见 `i-` 编号、实体 id 仅入 tooltip；无摘要时降级为原文折叠截断（实测 91 字）；收件箱「已澄清」区显示产物标题 `QA N4 产物任务`（tooltip 保留 `t-0007`）。
- **零残留**：三重 hash 逐字节一致；解析零写入与确认制不变；写入仍经单写者 + 原子写 + 审计（`inbox.apply`）。
