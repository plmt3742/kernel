# ADR-0039 · 个人页 + 习惯页——热力图迁往个人页、习惯独立成页、总览降级为入口卡

- 状态：已采纳
- 日期：2026-10-05
- 相关：ADR-0019（区域 / 目标 / 习惯可管理 + 打卡）、ADR-0022（界面状态保留）、ADR-0026（动作记录时间线）、ADR-0038（回顾自动化）

---

## 1. 背景

多习惯场景暴露了三个问题：

1. **只显示第一个习惯**：总览监视柱的「习惯打卡」取 `habits[0]`（纯 id 顺序），h-0001 未必是用户最关心的习惯；
2. **打卡断点**：总览是**唯一**打卡入口且只服务第一个习惯，其余习惯必须进设置页才能打卡——每天要做的动作藏在管理页里；
3. **无全局视角**：多习惯时看不到「今天达标几个、各自连续多久」，也没有一处回看「我每天在这个程序里做了些什么」。

所有者提出重构方向：做一个**个人页**（头像 / 姓名等资料 + GitHub 风格贡献日历 + 动作时间线），把热力图从总览迁过去；**习惯独立成一个页面**（打卡等操作集中）；总览的习惯部分只留一张**入口卡**（常用习惯 + 点击进习惯页）。

## 2. 决策

### 2.1 习惯页 `/habits`（一级导航 07）

- 全部习惯以卡片呈现：今日打卡开关（紧凑 pill，`✓ 今日已打卡` / `今日打卡`，toast + 撤销）、连续 / 最长 / 累计统计、可折叠的 16 周热力图、编辑 / 删除（删除入回收站、可撤销）、「新建习惯」。
- **习惯的新建 / 编辑 / 删除从设置页迁出**（设置页只保留外观 / AI / 标签 / 区域 / 目标等）；`relations.deepLinkOfId` 的 `h-` 映射改为 `/habits?habit=<id>`，习惯页据此直接打开编辑弹窗。
- 数据 / 端点 / 打卡语义**完全复用**（`POST /api/habits/:id/checkin|uncheckin`），本切片只搬动信息架构。

### 2.2 个人页 `/profile`（顶栏头像进入，不占一级导航）

- **资料**：`config.owner` 复用为显示名，新增可选 `bio`（≤160）与 `avatarPath`；头像为本地图片文件（`data/files/profile-avatar-<ts>.<ext>`，png / jpeg / webp / gif ≤2 MB），端点 `POST /api/profile/avatar`（RAW）/ `POST /api/profile/avatar/remove` / `GET /api/profile/avatar`（流式 + `nosniff` + `no-store`），审计 `profile.avatar`；无头像时用姓名首字母（monogram）兜底。**头像只存本地**，不进版本库、不进安装包。
- **活跃日历**：`GET /api/activity/summary?days=N`（默认 140、clamp 7..400）读取审计日志按**本地日**聚合、零填充缺失日；**排除** `config.update` / `ai.key.update` 两类设置噪音，其余真实写入（含 `habit.checkin`）都计入。一张图同时覆盖「习惯打卡」与「创建日程 / 完成任务 / 建项目」等活跃动作，GitHub 贡献图样式（5 级强度 + 月份 / 星期轴 + 图例 + 汇总行）。
- **动作时间线**：复用既有 `ActivityTimeline`（`GET /api/activity`，只读、日分组、筛选、深链），不新造。
- 入口：顶栏右上头像按钮 + 命令面板「个人页」动作；`nav.ts` 增 `EXTRA_PAGES` 使 `navByPath` 仍能解析标题（不进侧栏轨道、不进命令面板导航组）。

### 2.3 总览习惯块 → 入口卡

- 显示 `习惯 · 今日 N/M` + 若干「常用习惯」（近 30 天打卡次数降序，并列看当前连续）chip（名称 + 今日状态，**非交互**）；**整卡是一个按钮**，点击进 `/habits`。
- 热力图 / 打卡切换 / 统计从总览移除；零习惯空态保留（文案指向习惯页）。
- 移动端：`/habits` 为一级项（底栏第 7 项 + 更多），390px 零横溢。

### 2.4 config 写入的边界（记录在案）

原 `store.updateConfig` 白名单仅 `aiAutomation`。本切片需要 `owner` / `bio` / `avatarPath` 可写，按「本次不改 store.mjs」的约束，在 `server/index.mjs` 内以**串行链 + 原子写（write-file-atomic）+ 审计**镜像 store 的写入模式；`appConfigSchema`（catchall + 可选字段）保证旧配置可解析。**后续收敛项**：把该写入路径回移 `store.mjs`，恢复单一写者模块。

## 3. 边界（明确不做）

- 不新增数据实体（资料存 `config`，活跃日历为只读派生、零落盘）。
- 贡献日历不做权重 / 分类型筛选（计数即强度）；头像不做裁剪 / 压缩（仅类型 + 大小校验）。
- 总览入口卡不提供打卡（整卡为导航目标，避免嵌套交互）。

- 浏览器（Playwright + `/api/**` 拦截，真实数据零触达）：`qa-pages.py` **28/28 PASS**——资料卡与头像加载、活跃日历 5 级强度与汇总、时间线复用、顶栏头像 → `/profile`、习惯页双卡 / 打卡往返 / 热力图展开、总览入口卡 `今日 N/M` + 跳转、轨道与命令面板入口、1440/390 零横溢。
