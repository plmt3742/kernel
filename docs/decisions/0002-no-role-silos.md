# ADR 0002 · 不做身份/领域分区：角色即标签

- 状态：已接受
- 日期：2026-10-02
- 决策者：项目所有者
- 关联：`docs/00-DESIGN-BRIEF.md` §2、§3；`docs/01-PROJECT-BRIEF.md` §4

---

## 1. 背景

用户拥有多重身份：

`role:student`（学生）· `role:assistant`（学生助理）· `role:competition-head`（学生组织部长）· `role:acm`（算法实验室成员）· `role:monitor`（班长）· `role:vibecoder`（独立开发者）

一个直觉设计是把系统按这些身份切成一级分区（一个"学生组织"区、一个"学生助理"区、一个"学业"区）。这看似清晰，实则会制造信息孤岛：同一件事在多个分区重复，跨身份的相关性被结构切断，系统只服务单一身份。

## 2. 决策

**身份与领域只作为视图内的交叉筛选标签（tag），不作任何目录分区。**

- 一级信息架构只呈现通用循环：总览 / 收件箱 / 任务 / 日程 / 项目 / 资料 / 回顾 / 设置。
- 身份用 `role:` 命名空间，领域用 `topic:`，情境用 `context:`。
- 任何视图都能按这些标签交叉筛选，得到同一批数据的不同切面。

一句话：**身份是滤镜，不是抽屉。**

## 3. 理由

### 3.1 避免信息孤岛

按身份分区会把系统切成互不连通的抽屉。通用数据模型 + 标签筛选让所有事务共处同一批集合，跨界关联天然可行。

### 3.2 通用性来自轴，不来自分区

系统的 6 个通用轴（上下文、时间与紧急、能量、重要性、状态、有界标签）对所有实体一致。不同身份的事务共享同一套轴，因此可以自由交叉，这正是"通用"的实现方式。

### 3.3 符合"按可行动性组织"

PARA 精神是按可行动性组织，而非按身份/学科/领域切分。标签承担分类职责，结构只承担流动职责。

### 3.4 防止分类爆炸

标签命名空间化（`role:` / `topic:` / `context:`）并配合数量上限思路（Johnny.Decimal 精神），让标签保持有界可用，而不是演变成标签墙。

### 3.5 单一循环不被破坏

捕捉 → 澄清 → 组织 → 执行 → 回顾是一个连续循环。分区会强制在捕捉期就做身份归类，抬高摩擦，破坏"捕捉要快"的前提。标签允许先收集、后筛选。

## 4. 后果

- 数据层不出现按身份/领域划分的实体或目录。
- 视图一律提供筛选器，身份与领域在筛选器中出现，不在一级导航中出现。
- `data/meta/tags.json` 承载标签命名空间定义。
- 新成员（人或 AI）若提出"给学生组织单独开一个区"，应指向本 ADR。

## 5. 非目标

本决策不禁用身份信息本身。身份仍然重要，只是它的载体是标签而不是容器。它也不阻止在视图层提供"按身份聚焦"的预设筛选，只要底层仍是通用集合。

## 6. 备选方案

| 方案 | 结果 | 原因 |
|---|---|---|
| 通用循环 + 交叉标签（本决策） | 采用 | 无孤岛，通用性强，捕捉摩擦低 |
| 按身份/领域一级分区 | 否 | 制造孤岛，跨界切断，捕捉摩擦高 |
