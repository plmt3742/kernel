# ADR 0013 · 回顾报告升级（七段 · 有依据 · 可指导）+ 每次生成自动归档（Slice L）

- 状态：已接受
- 日期：2026-10-03
- 决策者：项目所有者两条指令：①「这些报告都不够详细，你需要调研如何才能将报告写得有价值和有参考以及指导性意见」+「以及通俗易懂」；②「你需要考虑将这些每次生成的报告都进行归档整理，按照时间进行保存，保存后可以在某个地方进行查阅」+ 实证（`.qa/v30/`）
- 关联：ADR-0005（AI 只建议不落盘）、ADR-0007（AI 周回顾 / 月回顾 · 写入路径 · 指标口径）、ADR-0011（先确认后写入）、`docs/02` §4、`docs/04` §4.10 / §9、`CHANGELOG.md`、`TASK_BOOK.md`、`.qa/v30/`

---

## 1. 背景

Slice C / F 已把「AI 读整个系统 → 生成周 / 月回顾草稿 → 用户编辑确认 → 落盘」跑通，但报告本身很薄：

- **输入侧**：注入模型的摘要只有「本期绝对值」——没有上一周期、没有阈值、没有环比；清单（完成 / 逾期 / 停滞）多为纯标题，缺 id 与天数，模型无从引用具体对象。
- **指令侧**：系统提示只要求「≤200 字、具体、克制」，未约束结构，模型自然会写「推进顺利、效率提升」这类无法验证的套话。
- **结果**：报告读起来像泛泛小结，缺数字依据、缺对比基准、缺可执行动作，也无从复核。

同时，每次生成只是一份内存草稿：用户若不点「保存回顾」就什么也不留；点保存也只存最新一条，没有「按时间回看每一份生成过的报告」的地方。

## 2. 决策

### 2.1 输入侧：摘要加环比、阈值与带 id 的清单（`server/ai.mjs` `buildReviewDigest`）

1. **上一周期指标 + 环比**：把 `now` 落在本周期起点前 1ms，复用 `computeWeekMetrics` / `computeMonthMetrics` 即可回退一个周期（周对周 / 月对月），得到上期指标；摘要新增「上期指标（对照）」与「环比（本 X 相对上 X）」两行（增量 + 百分比）。
2. **习惯切片 + 连续未达标周数**：每个习惯给出「近 7 天命中 / 上 7 天命中 / 目标 / 节奏 / 连续未达标周数」（后者为滚动窗口近似值，报告中允许标「数据不足」）。
3. **显式清单带 id**：完成清单改为 `t-xxxx · 标题`；逾期清单为 `t-xxxx · 标题 · 逾期 N 天`；停滞清单沿用 `p-xxxx · 标题 · 停滞 N 天 · 完成定义`。
4. **阈值常量**：显式写明「逾期 / 停滞 / 习惯未达标」的判定口径，供报告写「风险预警」时引用。

### 2.2 指令侧：七段结构 + 硬性规则 + 弱 / 强对照（`buildReviewSystem`）

`summary` 由「≤200 字一段」升级为**多段中文纯文本，恰好七段，每段以结论式标题开头**：

1. 结论速览（一句话 + 带对比基准的关键数字）
2. 本期数据解读（逐项数字 + 环比）
3. 趋势与对比（方向 + 连续周数）
4. 问题诊断（一层因果 + 数据证据）
5. 值得保留（至少一条在起作用的做法）
6. 下期行动（1–3 条 if-then：做什么 + 何时 + 完成标准 + 绑定任务 / 项目名或 id）
7. 风险预警（越线阈值 + 触发对象）

硬性规则：只用摘要中的数字 / 日期 / 标题 / id；每个判断带具体数字或对象；绝对值必带对比基准；禁套话（显著 / 一定程度 / 多方面 / 持续发力 / 闭环 / 赋能 / 值得注意 / 综上所述 / 整体向好）；短句主动语态；证据不足写「数据不足」；行动必须 if-then 含时间与完成标准；鼓励说明不确定性。提示内附「弱例（禁止）→ 强例（合格）」对照（用字母占位，避免示例数字污染）。

### 2.3 落地护栏：数字子集校验 + 单次纠正重试（`auditNumbers`）

生成后从 `summary` 抽取数字，断言其为摘要数字的子集：允许字面命中、由摘要数字加减 / 百分比派生、结构性小数字（≤3）、年份（1900–2099）。越界 → **单次纠正重试**（把越界数字回喂模型要求改正）；仍越界则保留结果并 `console.warn` 记录（不阻断生成，遵守「允许不确定性」）。沿用「指令式 JSON + Zod + 单次重试」既有模式。护栏函数导出于 `server/ai.mjs`，可独立单测。

### 2.4 输出形状：沿用 `summary` 字段，不新增结构数组

`summary`（`reviewDraftSchema` / `reviewSchema` 上限均 **2000 字**，七段 ≤800 字远未触顶）承载七段正文；`decisions` 为 1–3 条 if-then（服务端后校验截断至 3 条 × 200 字）；`staleAdvice` 语义不变。**不**引入 sections 数组——避免 schema / docs / 前端渲染 / ADR 四处同步改动的额外成本，且纯文本在 textarea 内仍可编辑。

### 2.5 自动归档：复用 `reviews` 实体（每次生成一条，编辑更新同条）

1. **生成即归档**：`POST /api/ai/review/draft` 在 AI 成功后，服务端经 `commit('reviews', …)` 落一条 review（`nextId('reviews')`、`periodKey`、`date=归档时刻`、`metrics`、`summary`、`decisions`、`staleProjectIds`、`source:'ai'`），审计 `review.create`（`detail.auto=true` / `grounded`）；响应附 `reviewId` / `archivedAt`。
2. **保存编辑更新同条**：新增 `POST /api/reviews/:id/update`（白名单仅 `summary` / `decisions`；保留 id / type / periodKey / date / metrics / staleProjectIds；递增 `updatedAt`；审计 `review.update` + `detail.fields`）。前端「保存回顾」在有 `reviewId` 时调用它——**不重复建记录**。
3. **版本语义**：**每次生成 = 新增一个归档版本**（时间序，可查阅、可删除）；同一周期可有多版，反映报告演进。这是 owner「每次生成都归档、按时间保存」的字面落地；因生成是用户显式动作，数量天然有界。**「保存回顾」不产生新版本，只更新当前 generation 对应那条。**
4. **删除**：沿用 `POST /api/reviews/:id/remove`（审计 `review.remove`）；报告历史与只读弹窗均可删除。

### 2.6 前端：七段正文渲染 + 报告历史（`src/views/Review.tsx`）

- 报告正文按换行切段渲染为独立区块，段首「标题：」渲染为小标题行（纯文本，无 `dangerouslySetInnerHTML`）；编辑态 textarea 加高（`rows=14`）。
- 新增**报告历史**栏（`REPORT ARCHIVE`）：全部 review 按 `date` 倒序，显示「类型 · 周期」+「归档时间 · AI 归档」；点击打开**只读**弹窗；弹窗内可删除。
- 卡片（周 / 月）承载「最新可编辑」：有内存草稿则编辑草稿，否则编辑最新归档（保存 = 更新同条）；历史入口一律只读。

## 3. 理由

- **报告要有依据才可参考**：把「上一周期 / 阈值 / 带 id 清单」喂进模型，判断才有对照基准与可复核对象；护栏进一步兜住数字幻觉。
- **结构与规则比语气更能治套话**：显式七段 + 禁词表 + if-then 行动约束，把「写得有价值、可指导、通俗」变成可检查的硬指标。
- **归档复用既有实体，零新增表**：`reviews` 已是「周期 / 指标 / 摘要 / 决策」的天然容器；`.catchall` + 可选 `source/updatedAt` 向前兼容旧记录（种子 rev-0001/0002 不动）。
- **更新同条而非重写**：保存编辑不制造重复，历史干净；「每次生成新增版本」又保留了「按时间查阅每一份生成」的诉求。
- **不阻断**：护栏越界重试一次即止，仍越界保留并记录——诚实呈现不确定性优先于硬失败。

## 4. 后果

- `reviewSchema` 增可选 `source` / `updatedAt`（向后兼容）；`reviewDraftSchema` 上限不变（summary 2000 / decisions ≤6）；服务端后校验截断 summary ≤2000、decisions ≤3×200。
- 新增 `POST /api/reviews/:id/update`（审计 `review.update`）；`POST /api/ai/review/draft` 变为**生成 + 自动归档**（审计 `review.create` · `auto`）。
- `generateReviewDraft` 返回值增 `prevMetrics` / `staleProjectIds` / `grounded` / `offenders`；导出 `auditNumbers` / `extractQuantities`。
- 前端 `ReviewDraft` 增 `reviewId` / `archivedAt` / `prevMetrics` / `staleProjectIds` / `grounded`；`mutations` 增 `updateReview`；`Review.tsx` 重构弹窗状态 + 报告历史。
- **与 ADR-0007 §2.5「草稿即草稿、确认才落盘」的差异**：本切片按 owner 明确指令，**生成即自动归档一条报告**（仅 `reviews`，不触任何任务 / 项目），编辑确认后更新同条；「确认才写入」对任务 / 项目等实体仍然成立。报告可删除，风险可控。
- 证据：`.qa/v30/`（服务端冒烟 + 护栏单测 + Playwright E2E + 截图 / 日志）。

## 5. 非目标（显式延后）

- **周 / 月之外的自定义周期回顾**；**报告导出（PDF / Markdown）**；**跨报告趋势汇总**（如「连续 N 期逾期上升」的跨期图表）。
- **`migrated` 真实统计**（无编辑追踪来源，仍可缺省，见 ADR-0007）。
- **报告编辑的字段级撤销**（当前撤销 = 删除整条归档，与既有 review.remove 语义一致）。
- **生成过程的 SSE 过程可视**（本切片沿用同步草稿路径）。

## 6. Slice U 修订：可读性（阅读视图）· 同期口径 · 去重（2026-10-03）

owner 反馈「生成的报告可读性太差」——截图显示七段正文被塞进一个大 textarea 当作一整块密文；且进行中的月回顾拿「本月 3 天」去比「上月整月」（苹果对橘子）；「下期行动」段与 `decisions` 逐字重复。本切片针对这三点修订，**不改变 §2.5「生成即归档 / 保存更新同条」的归档语义**。

### 6.1 阅读视图（默认）+ 编辑切换（前端）

- 新增 `src/lib/reviewReport.ts`：`parseReviewSummary()` 把 `summary` 拆成七段（`{ label, body }`），兼容「结论速览：…」与「一、结论速览」两种标题写法；别名归一（本期数据解读 → 数据解读、趋势对比 → 趋势与对比）；无法识别分节时回退整段渲染（旧归档 / 手写正文）。规则与 `server/ai.mjs` 同源，勿单边改动。
- `src/views/Review.tsx`：报告弹窗**默认阅读视图**——「序号 + 标题行 + 正文段落」的安静分栏（`.k-report__sections` / `.k-report__section`），舒适行距（1.75）与测度（68ch），纯文本、无 `dangerouslySetInnerHTML`。底栏「编辑」切到既有 textarea、「完成」切回；保存 / 重新生成流程不变。报告历史（只读）弹窗复用同一阅读视图。样式 token-only（`views.css`；`shell.css` 给 `.k-modal--report` 加 `max-height` 让长报告内滚、底栏常驻）。
- 数字护栏 `auditNumbers` 为文本级、与渲染无关，保持生效；编辑 / 保存 / `update` 流程未改。

### 6.2 同期口径（服务端 · 核心修复）

- `reviewWindows(now, monthly)`：本节窗口 + 上一周期**同等已走完长度**的对照窗口。月：本月 1..N 日 ↔ 上月 1..N 日（短月按上月末截断：`min(prevStart + elapsed, periodStart − 1ms)`）；周：本周至今 ↔ 上周同一星期数。
- `generateReviewDraft` 改用 `computeSameWindowPrevMetrics()` 求 `prevMetrics`。旧实现把 `now` 落在周期起点前 1ms 回退，得到的是**整**上一月 / 周——进行中周期因此苹果对橘子。
- 摘要 `prevLabel` 改为「上X同期」并附对照窗口日期；`elapsedDays < 7` 时追加【窗口说明】——要求在结论或风险里自然说明不完整，**禁止以「窗口仅 N 天」作为结论开场**。

### 6.3 去重与可读性规则

- `dedupeActionSection(summary, decisions)`：把第 6 段「下期行动」整段替换为一行指针「下期行动：见决策区（N 条）。」，完整 if-then 只留在 `decisions`——从构造上杜绝逐字重复（`decisions` 为空时不动原文，避免丢失唯一行动记录）。
- `formatDelta(cur, prev)`：基准 ≥5 才出百分比，基准 <5 只给绝对变化 + 基准（避免 0 / 1 基准下百分比失真）。
- `buildReviewDigest` 清单改为「标题（id）」标题优先；`buildReviewSystem` 增补规则：叙述优先用对象标题、id 仅在 `decisions` 行动里为绑定对象时括号补充（可选）；百分比基准规则；窗口不完整时的自然说明要求。

### 6.4 验证

- `.qa/v32/guard-unit.mjs` **25/25**（同期窗口语义：月 1..N vs 上月 1..N / 短月截断 / 周同一星期数 / 旧口径对照；分节 7 段与编号标题；去重指针与无逐字重复；百分比规则）。
- `.qa/v32/smoke-u.mjs` **23/23**（真实 monthly 一次：解析恰 7 段且标题齐全、第 6 段为指针、summary 无 decisions 逐字原句、无小基准硬算百分比、结论不以「窗口仅 N 天」开场、自动归档 + 审计 + 零残留 + 所有者未动）。
- `.qa/v32/slice-u-verify.py` **32/32**（默认阅读视图无 textarea、七段分节、编辑 ↔ 完成、保存更新同条、历史阅读渲染、删除回基线、移动 390 零横溢、控制台 0、零残留 + 所有者数据未动）。
