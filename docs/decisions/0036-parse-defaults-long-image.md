# ADR-0036 · 收件箱解析默认时间/地点与长图分片（QA v73 批次）

- 状态：已采纳
- 日期：2026-10-04
- 相关：ADR-0023（公告解析 / 截图接入）、ADR-0034（事件识别 · 规则 12）、ADR-0029（来源摘要）、ADR-0027（链接阅读）、ADR-0033（联网检索）

---

## 1. 背景与反馈

所有者（同一条批次诉求的解析 / 图片部分）：

> 「收信箱的 AI 需要更加智能……它最好还是能把时间点安排得比较好。比如说我说今天晚上要干嘛干嘛，那它就可以把时间大概定在晚上的某个点，通常我们可以定为 7 点或 8 点……比如说吃晚饭的时间，我说今晚要去吃什么什么晚饭，那时间一般就定成 6 点……我说要去大鱼吃什么什么，那它的地点最好还是能给我显示为那个餐厅的名字……它最好还是能把标签给我整出来，比如这个事情属于『吃饭』……在解析的时候，也要让它能够知道现有的标签和项目都是什么……它目前好像不具备阅读大的图片的能力……我刚才长截图了一个 1.2M 的聊天记录，结果它阅读超时。」

两个缺口：① 事件解析缺「系统认可的默认值」——模糊时段词（今晚 / 明晚 / 周六下午）此前保守丢弃或整日化，`location` 与活动标签缺提取规则；② 图片解析把整张大图作为单个 file part，1.2MB 长截图易超时。

## 2. 决策

### 2.1 解析默认时间/地点（提示词规则 12 扩充）

- **默认钟点补全**（系统认可的默认值，**不算编造**）：有日期（含今天 / 明天 / 后天 / 周X）但只有模糊时段词时，按默认钟点补全——早上 08:00 · 上午 09:30 · 中午 12:00 · 下午 14:30 · 傍晚 17:30 · 晚上 / 今晚 **19:30**；**用餐语境**：早饭 07:30 · 午饭 12:00 · 晚饭 / 晚餐 **18:00** · 夜宵 21:30。示例：「今晚去某餐厅吃自助」→ 今天 18:00；「明晚开会」→ 明天 19:30；「周六下午打球」→ 本周六 14:30。
- **地点提取**：内容含具体场所 / 店名 / 房间名（如「某餐厅」「某教室」）→ 填入 event `location`（≤50 字，只写场所名）；无法确定则省略。
- **标签与项目感知**：解析摘要注入现有标签 / 项目清单（既有机制）；活动类内容（吃饭 / 聚餐 / 面试 / 考试 / 运动 / 开会）在确无合适既有标签时提议活动标签（如 `topic:吃饭`），复用优先；落盘仍走既有 `ensureTags` / apply 链路。
- 保守边界不变：连日期都无法推出 → **不产出 event**（宁可 task + facts），绝不编造日期。

### 2.2 长图分片（>400KB 大图客户端切片 → ai-preview → 多发 file part）

- **客户端切片**（`src/lib/imagePreview.ts` `sliceImageForAi`）：图片 >400KB（`PREVIEW_MIN_BYTES`）时按纵向切 ≤6 张 JPEG——先按长边 ≤1600 等比压缩，若片数超 6 再等比缩小到恰好 6 张（片高 1600、质量 0.82）；小图 / 非图片 / 解码失败 / 画布不可用一律返回 `[]` **回退「原图单 part」路径，切片失败不阻断投递**。
- **分片上传**：`POST /api/inbox/<id>/ai-preview?index=1..6`（RAW body = JPEG；服务端校验 id / 条目存在且为图片 / index 1..6 整数 / 体积上限），落 `data/files/<id>-ai-<n>.jpg`——**派生辅助资源**（无审计；随条目删除一并清理）。
- **解析侧**：图片条目解析时收集 `-ai-<n>` 分片为多个 opencode file part（≤6 张并发给模型）；无分片回退单图路径 `buildImagePart`（兼容旧数据 / 未切片图片）。图片解析超时放宽至 **180s**。
- 前端投递流程：`uploadInboxFile` 内先切片、逐片经 ai-preview 上传（**在返回前完成**），再进入既有「文本即解析」管线。

## 3. 边界

- 只处理图片条目（`isImageFile`）；非图片 400、index 越界 400、条目不存在 404。
- 分片无审计、不改写原附件 `<id>-<name>` 路径；不新增任何出站面（只走本机 opencode file part）。
- 默认值仅限「钟点词表 + 用餐语境」；**明确时间照准、模糊才补**。
- 长图仍是「整图切分」，不做 OCR / 不做跨页拼接；每次解析最多 6 个分片。

## 5. 后果

- **正面**：模糊时段不再保守丢失（「今晚吃饭」→ 18:00 直接进日历）；地点名与活动标签自动提取；长截图（1.2MB+）解析不再超时。
- **代价**：默认钟点表是「系统承诺」，须与所有者习惯一致（本表按所有者口述校准：晚 7–8 点 / 晚饭 6 点）；分片让单次解析多发 ≤6 个 file part（耗时 ↑，已放宽超时到 180s）。
- **约束**：不做图内文字的 OCR 替代（仍依赖模型读图）；分片是派生资源，不参与备份语义之外的任何用户数据面。
