# 06 · 路线图

> 本篇展开宪法 §1 的版本节奏，给出 v0.1 到 v1.0 的里程碑计划。未来版本的内容是规划，实现时若需偏离应开新 ADR。
> v0.3.0 起视觉方向改为「C 柔暗夜色 + B 柔影悬浮」，见 `docs/decisions/0003-design-direction-v2.md`。因该次重做插入，数据服务 / AI / 自动化顺延为 v0.4 / v0.5 / v0.6。

## 2. v0.1.0 工程地基（已完成）

交付：

- 文档系统：`README.md`、`AGENTS.md`、`CHANGELOG.md`、`TASK_BOOK.md`、`docs/01` 到 `docs/07`、ADR 0001 与 0002。
- 项目宪法 `docs/00-DESIGN-BRIEF.md` v1（2026-10-02）。
- Vite + React 19 + TypeScript（strict）脚手架，原生 CSS token 体系。
- 路由骨架（8 条路由）。
- 文件式数据层：`data/` 一记录一文件，前端经 `src/lib/data.ts` 读取。
- 种子数据与元数据，以 2026-10-02 为"现在"。

## 3. v0.2.0 高保真前端原型（已完成）

交付：把宪法 §4 的视图规格落成可演示、可交互、符合设计系统的高保真原型。

- 设计 token 落地为 CSS 变量；布局骨架（Index Rail 96px / 64px + StatusBar + 主内容区）。
- 双主题（亮/暗）与 FOUC 防护。
- 八视图：总览 / 收件箱 / 任务 / 日程（P0）、项目 / 资料 / 回顾（P1）、设置（P2）。
- 命令面板（`Ctrl+K`，cmdk）；动效技法（共享元素变形、stagger、数字滚动、完成划线塌缩、现在线呼吸、Ticker、命令面板升起）。
- 无障碍：reduced-motion 降级、焦点环、键盘全可达。
- 该版本采用硬瑞士风，经所有者验收后否决；缺陷归档于 `.qa/QA-REPORT-v0.2.md`。

## 4. v0.3.0 视觉方向重做（已交付）

目标：按所有者选定的方向重做全站视觉，并修复 v0.2 QA 的全部缺陷。

范围：

- **方向**：C 柔暗夜色为默认基底 + B 柔影悬浮语言融合（清 ADR-0003）。
- **暗色（默认）**：`#0F0F10` 底、`#1A1A1C` / `#212124` 表面、`#F4F4F5 / #A1A1AA / #929298` 文字、圆角 16、无硬边线、柔辉光。
- **柔影悬浮**：卡片/面板/瓦片静置柔影 + 顶部微高光；交互卡片/行悬停 `translateY(-2px)` + 更深柔影。
- **亮色**：B 的暖雾柔光（`#F7F6F3` / 白卡 / `#1C1917` 系文字）。
- 默认暗色：更新 FOUC 脚本与主题 hook（无保存偏好即暗色，已保存切换仍优先）。
- 全站重皮：应用壳、全局组件、8 视图。
- QA 缺陷修复：M1 选中 chip 文字可读；M2 强调色文字过 AA（日历激活日 / Toast 标签）；M3 按钮 reset 补 `padding:0`；M4 日历 scroll-to-now；M5 命令面板/抽屉焦点圈闭 + 还原；P7 强调色退出图表数据系列；P8 TODAY 瓦片逾期信号归位；P9 token 纪律；P10 删除死代码 HeatGrid、spine 短事件不裁剪、等宽栈补 CJK。
- 文档：宪法 §5 升 v2、ADR-0003、设计系统 v2、文件树、CHANGELOG v0.3.0、TASK_BOOK、AGENTS、本路线图重编号。

**追加波次（同属 v0.3.0，均为所有者验收驱动）：**

- **版式重排（结构层）**：版心居中 `--content-max: 1240px`；总览改 C 稿式 bento（状态 chips / 紧凑日程 ScheduleList / 三层瓦片 / 项目进度卡）；任务筛选折叠「更多筛选」；收件箱扁平化；全站统一节奏。证据 `.qa/v04/`。
- **数理自适应（公式层）**：字号/间距 Utopia 流体 `clamp`（锚点 390/1440，1440 零回归）；φ 间距层级（1 : φ : φ² : φ³）；五具名容器查询（route / stat / task / pcard / drawer）；死代码清理；`docs/08-MATH-SYSTEM.md`。证据 `.qa/v05/` 四档实测。
- **验收修复**：命令面板焦点还原与水平居中（`margin:0 auto`，不依赖被 Motion 覆盖的 transform）；灰阶对比校正（暗色 `--muted #929298`、亮色 `--ink-2 #665F59` `--muted #6E6862`，全表面 ≥4.5:1）。

不在范围内：持久化写入、数据服务、AI 实际调用（顺延至 v0.4 / v0.5）。

## 5. v0.4.0 数据服务

目标：把写入从 localStorage 原型态迁移为受控的本地服务。

范围：

- Node 单写者数据服务，唯一写入路径。
- 原子写入（write-file-atomic）。
- Zod schema 校验，写入前全量校验。
- 审计日志 `data/activity.jsonl`。
- 前端写入改造为经 API 调用，移除原型态 localStorage。
- 数据迁移与备份策略。

约束：浏览器禁止直接写文件；多进程禁止直接写文件；派生值仍运行时计算。

## 6. v0.5.0 opencode AI 接入

> 实现记录（2026-10-02 首个切片）：收件箱「AI 解析」已交付；实证修正见 ADR-0005（serve 端口 / 指令式 JSON / variant 档位）；SSE 流式列为后续增量。

目标：把 opencode 作为"大脑"安全接入。

范围：

- 本地 Node 服务代理链路：网页 → 本地服务 → `opencode serve`（仅 `127.0.0.1:4096`）。
- `@opencode-ai/sdk`：`createOpencodeClient`、`session.create` / `prompt` / `prompt_async`。
- `event.subscribe`（SSE）推进度与流式结果。
- 结构化输出 `format: json_schema`，用于生成待办、摘要、澄清建议。
- 结果写回 `data/`，敏感操作显式确认。
- AI 建议卡从占位转为可用。

安全纪律：opencode 永不直接暴露到局域网；`OPENCODE_SERVER_PASSWORD` 保护本地服务到 opencode 的连接。

规划范围：

- 文档与代码全量对齐审计。
- 明确稳定版的兼容与迁移策略。
