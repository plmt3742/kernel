# 07 · 运行与部署

> 本篇展开宪法 §6.4，给出本地运行、局域网访问、Windows 防火墙与常见问题的操作说明。
> 本项目仅本地运行，不发布公网。

---

## 1. 环境要求

- Node.js 18+ 与 npm。
- Windows 桌面环境（本项目直接跑 Windows 侧，不使用 WSL）。
- 手机与电脑处于同一 WiFi（局域网访问时）。

## 2. 安装

```bash
npm install
```

可选：生成种子数据（写入 `data/`）。

```bash
npm run seed
```

## 3. 本地运行

```bash
npm run dev
```

该命令由 `scripts/dev.mjs` 一并启动两个进程：

1. **数据服务**（`server/index.mjs`，仅监听 `127.0.0.1:4097`，写入的唯一路径）；
2. **Vite 开发服务器**（`http://localhost:5173`，把 `/api` 代理到数据服务）。

浏览器打开 `http://localhost:5173`。状态条右下角的胶囊会显示数据服务状态（在线 / 离线只读）；设置页可查看最近的审计活动。

默认只监听本机。若要让局域网内的手机访问，见下一节。

> 只启动前端（不启动数据服务）时：`npm run dev:web`。此时界面以只读方式可用，写入操作会提示失败。

## 4. 局域网访问（手机 → PC）

### 4.1 开发模式

```bash
npm run dev -- --host
```

数据服务与 Vite 一并启动（`--host` 透传给 Vite）。Vite 会监听所有网卡，并打印可用的局域网地址。手机浏览器访问：

```text
http://<电脑局域网IP>:5173
```

手机上的写入同样经 Vite 的 `/api` 代理进入数据服务（单写者纪律不破；数据服务本身不暴露到局域网，仅监听 `127.0.0.1:4097`）。

获取电脑局域网 IP：命令行执行 `ipconfig`，查看当前无线网卡的 IPv4 地址（形如 `192.168.x.x`）。

### 4.2 生产构建与预览

```bash
npm run build
npm run preview -- --host
```

手机访问：

```text
http://<电脑局域网IP>:4173
```

### 4.3 配置说明

`vite.config` 中 `server.host: false` 与 `preview.host: false`——dev / preview 默认只监听本机，局域网 / 手机访问需显式 `--host`。

**安全含义**：这两个选项会让 Vite 监听所有网卡，同一局域网的任何设备都能访问该服务。因此：

- 仅在可信 WiFi（家庭、个人热点）下使用。
- 用完即关闭，不要长期开着 `--host`。
- 公司、公共、咖啡厅等不可信网络下不要开启。
- 本项目不面向公网，不要在路由器上做端口转发或暴露到互联网。

纯 HTTP 的局域网 IP 不是安全上下文（secure context），因此浏览器不会提供 PWA、摄像头、剪贴板完整能力等。本项目不需要这些能力，所以 HTTP 可接受。

## 5. Windows 防火墙

首次以 `--host` 运行或手机无法访问时，Windows 防火墙可能拦截 Node：

1. 弹出"Windows 安全中心"提示时，勾选**专用网络**并允许访问。
2. 若误点了"取消"，进入"Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙"，找到 Node.js 并勾选专用网络。
3. 仍无法访问时，确认手机与电脑在同一网段，并使用电脑的局域网 IP（不是 `localhost`、不是 `127.0.0.1`）。
4. 部分网络启用了"AP 隔离"或客户端隔离，会阻止设备互访，需要换网络或关闭该功能。

## 6. 常见问题（FAQ）

**Q：手机打不开 `http://192.168.x.x:5173`。**
A：按顺序排查：是否用了 `--host`；防火墙是否放行；手机与电脑是否同一 WiFi；IP 是否写对；路由器是否启用 AP 隔离。

**Q：`localhost` 能开，手机不能开。**
A：`localhost` 只在电脑本机有效。手机必须用电脑的局域网 IP。

**Q：端口被占用。**
A：Vite 会自动切换到下一个可用端口，注意看终端输出的实际端口；也可用 `--port` 指定。

**Q：中文显示成方框或字体不对。**
A：字体应自托管（`@fontsource-variable/inter`、`@fontsource/jetbrains-mono`）。检查是否误用了 CDN，项目禁止 CDN。

**Q：主题切换时闪白。**
A：需在首帧渲染前读取 localStorage 并设置主题类，防 FOUC。检查挂载入口的逻辑。

**Q：数据改了页面没更新。**
A：v0.4 起 `data/**` 的文件改动不再触发热更新（避免写入后整页刷新打断操作）。应用内的写入会即时反映；手工修改数据文件后刷新页面（或切换窗口触发重水合）即可看到。

**Q：数据服务离线了怎么办？**
A：状态条胶囊会显示「数据 · 离线（只读）」，此时界面仍可浏览，写入会收到失败提示。运行 `npm run dev`（或 `npm run server` 单独启动数据服务）恢复；回到页面点一下窗口即可自动重连（聚焦重水合）。

**Q：`4097` 端口被占用 / 提示已有数据服务在运行。**
A：说明已有一个数据服务实例（例如另一个终端仍在运行 `npm run dev`）。关掉多余实例即可；数据服务设计为单实例。

**Q：怎么查看数据变更记录？**
A：审计日志在 `data/activity.jsonl`（每次写入追加一条），设置页「数据服务」面板也会显示最近 8 条。

**Q：opencode 能被手机访问吗？**
A：不能，也不应该。opencode 仅监听 `127.0.0.1:4096`，永不暴露到局域网。AI 能力（v0.5）由本地 Node 服务代理，手机访问的是前端与本地服务，不是 opencode 本身。

**Q：数据会被上传到云端吗？**
A：不会。数据以文件形式保存在本地 `data/`，本项目不发布公网。未来 AI 能力也走本地 opencode。

**Q：用 WSL 可以吗？**
A：本项目直接跑 Windows 侧，规避 WSL 端口转发的麻烦。若坚持用 WSL，需要额外做端口转发配置。
