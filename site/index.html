为什么

事情没有变多，只是散开了。

聊天里的约定、相册里的截图、下载文件夹里的 PDF、收藏夹里的链接、课表上的教室，还有突然想到的一件事。它们都重要，只是不在同一个地方。

很多时候不是记不住，是入口太多。多一个 App，就多一次切换、一次重复录入、一次「回头再整理」。真要找的时候，往往只剩一个模糊的印象。

KERNEL 想做的事很简单：把收进来、想清楚、放好、做掉、回头看这五步放回一条线上。身份和领域只是标签，事情还是按时间、项目和区域来放。

02

功能

一页只做一件事。

收件箱收东西，助手回答问题，资料和笔记把东西留下来。下面三张图，是日常用得最多的三个页面。

01 / 收件箱

先收下，再想清楚

一句话、一张截图、一个文件、一个链接，都可以先丢进收件箱。AI 读一遍，告诉你它更像任务、日程、笔记、资料还是项目。你确认之后才写入，原条目也保留。

  • 文字、截图、文件、链接，都从这里进

    先收进来，不要求当场分类。

  • AI 只给建议

    它只出提案，不动文件。

  • 确认之后才写入

    原条目保留，保存后还能撤回。

02 / 助手

先问，再做。

可以直接问日程、任务、笔记和资料，也可以让它帮你记一件刚发生的事。要写入时，它先把结果给你看，你点确认才保存。不想用 AI 时，手动记录和整理也能走完同样的流程。

  • 回答基于你的数据

    数据里没有的，不编。找不到就说找不到。

  • 写入前先给你看

    确认前不改任何文件。

  • 离线也能手动记录

    AI 不可用时，记录、整理、回顾照常。

03 / 资料与笔记

看过的，能找回来。

笔记用 Markdown 写，可以一层层做摘要，新内容只追加在末尾，不改原文。文件资料会留下简介、原文和本机位置，再用标签、区域和项目串起来。

  • 原文留着

    摘要只追加，不改写已有内容。

  • 文件有简介和位置

    收进来的资料仍然找得到、打得开。

  • 标签、区域、项目能互相找到

    从任何一条记录都能走到它的上下文。

03

数据在哪

数据在你自己的电脑上。

一条记录一个文件，UTF-8 JSON，能读、能备份、能搬走。两个本机服务只监听 127.0.0.1，不发布到公网。

没有云同步，没有账号，也没有把数据放在别人的服务器上。整个 data/ 目录可以直接拷到另一台电脑；卸载程序时，数据会保留。只有你主动使用 AI 时，相关请求内容才会发给模型。

05

常见问题

你可能想问。

关于数据、AI、手机和安装的六个回答。

还有别的问题？去 GitHub Issues 提问 ↗

数据存在哪里？

存在你电脑上的 data/ 目录，一条记录一个 JSON 文件；卸载程序时数据会保留。

需要联网吗？

应用本身离线可用；只有向 AI 提问或让它解析内容时，相关内容才会经本机服务发给模型。

AI 会自动改我的东西吗？

不会。它只给建议，写入前会先把结果给你看，你确认才保存。对话和草稿默认不存档。

支持手机吗？

连同一个 WiFi 时可以用手机浏览器打开；目前是本地单用户版本，没有独立的手机 App。

需要装 Node.js 吗？

用 Windows 安装包不需要；从源码运行需要 Node.js 20.19+ 或 22.12+。

数据能迁移吗？

能。整个 data/ 文件夹可以直接拷到另一台电脑；格式是 UTF-8 JSON，不依赖云端。
