KERNEL 1.1 / 本地优先的个人事务系统 / WINDOWS RELEASE 1.1.0 — 2026

课表、作业和项目， 现在有一个系统。

KERNEL 是一个本地优先的个人事务系统。收件箱、今天、任务、日程、课表、项目、笔记、资料、习惯、踪迹和回顾，都在同一个 Windows 应用里。数据保存在你自己的电脑上。

01

THE IDEA / 为什么

把每天要做的事，
收进一个系统。

课程通知在群里，实验报告在文件夹里，截止日期在脑子里。KERNEL 把这些记录放进同一个本地应用，再用同一条流程处理：先收进来，决定它是什么，放进今天或项目，做完后回顾。

  3. 03组织ORGANIZE

IN PRACTICE / 具体场景

三个具体场景。

CASE 01 / EXAM WEEK

考试周

第 12 周，单周。周一到周五有课，周五 23:59 交实验报告。复习计划放在「期末复习」项目下，按章节拆成子任务。每天打开今天，先看课和到期任务；周日回顾时看哪门课一直没动。

今天 · 项目 · 回顾

CASE 02 / GROUP WORK

社团活动

群里发来迎新活动通知：9 月 20 日 14:00，体育馆，需要场地申请和物料采购。截图丢进收件箱，AI 拆成一条日程和两项任务，全部挂进「迎新活动」项目。活动结束后，回顾里能看到这次筹备做了什么。

收件箱 · 日程 · 任务 · 项目

CASE 03 / SIDE PROJECT

个人项目

读到的文章进资料，笔记做 L1/L2，项目写清完成定义。做完一步记一条踪迹。月底回顾时，能看到实际推进的几件事，而不是只记得「好像很忙」。

资料 · 笔记 · 项目 · 踪迹 · 回顾

05

YOUR FILES / 数据在哪

你的数据，
是一个文件夹。

KERNEL 没有账号，也没有云端数据库。任务、日程、笔记、资料、收件箱和附件都在安装目录的 data/ 里，一条记录一个 UTF-8 JSON 文件。备份就是复制整个文件夹；换电脑也是复制过去。卸载程序时，data/ 保留。

  • 01

    AI 是可选层。不配置模型也能手动记录、整理和回顾；只有你主动使用 AI 时，请求才会离开电脑。

  • 02

    写入前一定确认。AI 只出建议或草稿，对话默认不落盘。

  • 03

    整个 data/ 可以带走，不依赖数据库导入导出。

TECH DETAILS / 技术细节

数据服务只监听 127.0.0.1:4097，AI 代理在 127.0.0.1:4096。所有写入经过 Zod 校验、原子写入和审计日志。

~/KERNEL/data LOCAL
tasks/任务记录+

一条任务一个 JSON 文件，路径形如 t-0012.json。子任务、截止时间和项目关联都在文件里。

events/日程+

组会、考试、约谈各自是一条记录，和时间、地点放在一起。

notes/笔记与层级+

Markdown 正文和蒸馏层级；原文保留，不在蒸馏时被覆盖。

resources/资料与原文+

简介、原文、链接和本机文件位置；文件本身在 files/。

files/截图与附件+

从收件箱收进来的图片、PDF 和其他附件。

meta/标签、学期、配置+

标签注册表、学期周次和本机设置。没有模型凭据也能打开应用。

activity.jsonl审计日志+

每次写入追加一条，方便回看发生过什么。

FAQ

FAQ / 常见问题

你可能想问。

关于数据、AI、手机和迁移，先把话说明白。

还有别的问题，可以在 GitHub 上提 issue。

去 GitHub 提问 ↗
01和 Notion / Obsidian / 滴答清单有什么不同？+

它们各自解决文档、笔记、任务的一部分。KERNEL 把课程、任务、日程、项目、资料和回顾放在同一份本地数据上，省掉在几个工具之间搬运。

02数据存在哪里？+

安装目录的 data/ 里，一条记录一个 JSON 文件，附件在 data/files/。

03需要联网吗？+

手动记录、整理、查看和回顾都能离线。只有你主动使用 AI 时，请求才会离开电脑。

04AI 会自动改我的东西吗？+

不会。它只出建议或草稿；写入要你确认。

05有手机 App 吗？+

没有独立 App。电脑和手机连同一个 Wi-Fi 时，可以在设置里开手机访问，用手机浏览器打开；电脑要开着。

06需要安装 Node.js 吗？+

安装包不需要。从源码运行需要 Node.js 20.19+ 或 22.12+。

07能迁移吗？+

退出应用，把整个 data/ 复制到新电脑的安装目录。

08免费吗？+

MIT 开源。下载和使用不收钱；AI 模型的费用由你自己的 DeepSeek 账号承担。
